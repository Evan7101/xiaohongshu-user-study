小红书用户研究问卷 - 本地部署运行指南
============================================================

一、问卷结构（更新后）
-----------------------
每份问卷 = 1个小红书用户主页评价 + 10张图片真假判断 + 个人信息

- 5套问卷，每套对应1个AI生成用户 + 10张专属图片
- 每套问卷目标收集3份有效答卷（共15人）
- 后端智能分配：第一个打开链接的人→问卷1，第四个→问卷2...
- 如果有人点击了但未提交，系统会自动将后续访问者分配给缺额的问卷

二、前置准备
------------
1. 确保已安装 Python 3.x（无需任何第三方库）
2. 确保已安装 ngrok（用于公网访问）
   下载地址：https://ngrok.com/download
   注册账号后获取 authtoken：ngrok config add-authtoken <your_token>

三、填写真实数据
----------------
唯一需要编辑的文件：data/data.json

图片路径建议：
- 本地图片：放在 images/ 文件夹，路径写 "./images/xxx.jpg"
- 在线图片：直接写完整URL
- 建议每张图宽度1080px，压缩到500KB以内

四、启动服务器
--------------
打开终端，执行：

    cd C:\code_project\xiaohongshu-user-study
    python server.py

你会看到：
    问卷服务器已启动
    本地访问: http://localhost:8080
    数据保存: responses.csv
    分配记录: assignments.json

五、暴露到公网（ngrok）
-----------------------
打开另一个终端，执行：

    ngrok http 8080

复制 https://xxx.ngrok-free.app 这个链接发给受访者。
所有人打开的都是同一个链接，后端会自动分配不同的问卷。

六、监控数据收集
----------------
1. 查看已分配的问卷情况（实时）：
   直接打开 assignments.json 文件，里面记录了每个问卷的分配次数和成功提交次数：
   {
     "user_01": { "assigned": 3, "submitted": 2 },  // 分配了3人，2人已完成
     "user_02": { "assigned": 3, "submitted": 3 },  // 已满
     ...
   }

2. 查看答卷数据：
   打开 responses.csv（Excel 直接打开即可，UTF-8编码带BOM）

   CSV 长格式说明：
   - 每个受访者产生 12 行数据：
     * 1行 SectionA（该用户的4个维度评分+开放题）
     * 10行 SectionB（10张图片的真假判断）
     * 1行 Postsurvey（Q6使用频率 + Q9自信度）
   - 每行都有 "受访者ID" 和 "分配问卷" 字段，可用于关联同一人的所有回答

3. 要结束收集、停止服务器：
   在运行 server.py 的终端按 Ctrl+C

七、如果需要重启服务器
-----------------------
可以安全地停止再启动，assignments.json 和 responses.csv 会被保留并继续追加。

但如果想清空重新开始：
    del responses.csv
    del assignments.json
    python server.py

八、分配机制（无硬性上限，智能补足）
--------------------------------------
系统没有硬性人数上限，所有访问者都可以填写并提交成功。

分配逻辑：
1. 前15个访问者：按顺序分配，确保每套问卷至少被分配到3次
   （user_01×3 → user_02×3 → ... → user_05×3）
2. 15个之后：优先分配给「成功提交数不足3」的问卷（补足缺口）
3. 所有问卷都满3个提交后：继续均匀分配，超额收集

如果你只想收集恰好15份，在 assignments.json 中看到所有 submitted=3 时即可停止分享链接。

九、注意事项
------------
1. 服务器必须保持运行，否则新访问者无法分配问卷、无法提交数据
2. ngrok 免费版每次启动URL会变，如果要长期运行建议用 paid plan 或固定域名的方案
3. 不要在 debrief 页面之前告诉受访者内容是AI生成的（这是盲测设计）
4. 所有图片建议开启 lazy loading（已内置），减少移动端流量消耗

十、故障排查
------------
- 页面空白/加载失败：检查 data.json 格式是否正确（JSON语法）
- 图片不显示：检查图片路径/URL是否可访问
- 提交失败：检查 server.py 是否在运行，终端有无报错
- assignments.json 损坏：删除它重启服务器，系统会自动重建
